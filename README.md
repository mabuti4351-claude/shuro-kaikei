# 就労B型 生産活動 収支アプリ

就労継続支援B型の生産活動収支を、**全体**と**作業ごと**の両方で見られるWebアプリ。
これまでExcel（`就労会計2025.10～2026.9Book2.xlsm`）でやっていた出納帳＋ピボットを置き換えるもの。

## ファイル

| ファイル | 内容 |
|---|---|
| `shuro_kaikei.html` | アプリ本体（これ1つで動く） |
| `manifest.json` / `sw.js` / `icon.svg` | PWA用（デスクトップ・ホーム画面に追加できる） |
| `vercel.json` | Vercel公開用（`/` → `shuro_kaikei.html`） |
| `firestore.rules` | Firestoreのセキュリティルール |
| `data/2025年度_移行データ.csv` | 既存Excelから抜き出した139件（アプリ内にも同じものを内蔵済み） |

## データの持ち方

```
entries（明細1件）
  d: 日付 'YYYY-MM-DD'
  t: 'in' 売上 / 'out' 経費 / 'wage' 利用者工賃
  a: 金額
  j: 作業ID（'__common' = 共通・あとで分ける）
  c: 費目ID（経費のみ）
  m: メモ（摘要）
  p: 入金日（売上のみ）
jobs    作業マスタ
costs   費目マスタ
presets よく使う経費（業者）マスタ [{id, name, j, c}]
        → 経費入力画面に1タップボタンとして出る（作業・費目・業者名がまとめて入る）
settings { fyStart:10, alloc:'sales'|'manual'|'none', allocRatio }
```

- 年度は **10月はじまり**（設定タブで変更可）。
- 共通経費（食材費など、どの作業のぶんか分けにくいもの）は `__common` に入れておき、
  「収支」タブで **売上比率で自動按分** される（設定で「自分の比率」「按分しない」も選べる）。
- 利用者工賃は作業に按分せず、全体の収支からのみ引く。

## 簡易版／基準版

`settings.mode` で切り替える（設定タブ）。法人格は**有限会社**＝社会福祉法人以外の法人。

| モード | 用途 | 画面 |
|---|---|---|
| `simple` | ふだんの管理 | ホーム／入力／収支／明細／入金票／設定 |
| `standard` | 決算・提出 | 上記＋**決算（基準版）**タブ |

### 基準版で作る書類

厚労省「就労支援の事業の会計処理の基準」（平成18年10月2日 障発第1002001号）に準拠。
**年間売上5,000万円以下＋多種少額**のため、表2（製造原価明細書）・表3（販管費明細書）に代えて
**表4（就労支援事業明細書）**を作成する簡便法を採用（運用ガイドラインp15 注記\*2、p19）。

- **（表1）就労支援事業別事業活動明細書** … 作業種別ごとの列。
  `就労支援事業収益 X − 販売原価(A+B+C−D) = 就労支援事業活動増減差額 X−Y`
  A=期首製品(商品)棚卸高／B=当期就労支援事業費（表4より）／C=当期就労支援事業仕入高／D=期末製品(商品)棚卸高。
  表4ルートのため「当期就労支援事業製造原価」を「就労支援事業費」と読み替え、「就労支援事業販管費」は削除。
- **（表4）就労支援事業明細書** … Ⅰ材料費／Ⅱ労務費／Ⅲ外注加工費／Ⅳ経費 → 当期就労支援事業製造総費用
  ± 仕掛品棚卸 → 就労支援事業費。
- **（別紙1）就労支援事業事業活動計算書** … 当年度・前年度・増減。参考様式（「各法人が準拠する会計基準の様式で可」）。

### 実装のポイント

- 費目マスタに `grp`（材料費／労務費／外注加工費／経費／商品仕入）と `std`（表4の勘定科目名）を持たせ、
  日々の入力は簡易な費目名のまま、決算時に基準の科目へ自動集計する。
- `t:'wage'`（利用者工賃）は自動的に 労務費／利用者工賃 に計上。
- **作業別の列**は、直接費はそのまま、共通費・工賃・棚卸を売上比で按分。
  按分の端数は絶対値最大の列に寄せ、各列の和が合計欄と必ず一致するようにしている（`cell(obj, total)`）。
- 「多種少額の生産活動を行う等の理由により、作業種別ごとに区別することが困難な場合は
  作業種別ごとの区分を省略できる」（表1〜4共通）に対応 → `settings.stdJobBreakdown = false` で合計列のみ。
- 決算整理（棚卸・積立金）は `settings.fyData[年度]` に保存。
- **工賃の適正額チェック**：指定基準第201条
  `生産活動収入 − 生産活動に係る経費 = 利用者に支払う工賃`。
  積立金繰入額を控除したうえで、実際の支払工賃との差を表示する。

## 共通経費の2段階按分

共通経費は、**①福祉事業と生産活動に分ける → ②生産活動の分を作業別に分ける** の順に按分する。
①を入れないと、職員給与や水道光熱費のように福祉事業（給付費）と共用している経費が
まるごと生産活動の経費になってしまい、支払うべき工賃が過小に出る。

### ①福祉事業／生産活動（費目ごとに設定）

費目マスタの `prod` で決める。設定タブの「①生産活動が負担する割合」列。

| `prod` | 意味 | 例 |
|---|---|---|
| `'all'`（既定） | 全額が生産活動の経費 | 食材費、委託費 |
| `'auto'` | 収入比で自動 | 職員給与、水道光熱費、通信費 |
| 数値 0〜100 | 手入力の% | 面積比などで根拠がある場合 |

`'auto'` の割合 = 生産活動収入 ÷（生産活動収入 ＋ 福祉事業収入）。
**福祉事業収入（訓練等給付費）はTKCのPDFから取り込む**（`settings.welfareIncome['YYYY-MM']`）。
まだ取り込んでいないときは全額を生産活動として扱う（勝手に減らさない）。

> 按分の根拠は「合理的な基準」であればよく、面積比・従事時間比でもよい。
> 手間を考えて収入比を既定にしているが、費目ごとに手入力で上書きできる。

### ②作業別（既存）

①で残った生産活動の分を、費目ごとの按分先へ売上比で配る。
`calc()` と `calcStd()`（表4）の両方に同じ按分が入っている。

## 会計ソフト（TKC）のPDFから経費を取り込む

TKCの **部門別科目残高推移表** のPDFを設定タブで選ぶだけで、
決めておいた科目の月ごとの金額を「共通（あとで分ける）」の経費として登録する。

- `settings.tkcDept` … この事業所の部門コード（例 `030`＝ジョブきらめき、`031`＝水釜）。
  全部門が入ったPDFでも、`部門： 030 …` の行を探して**その事業所のページだけ**を読む。
- `settings.tkcAccounts` … 科目の一覧 `[{code, name, kind, prod, amt}, …]`。
  **「PDFから科目の一覧を作る」でPDFに載っている科目が全部並ぶ**（金額つき）。入力は不要。
  1科目1行で、扱いを1つ選ぶだけ ＝ 取り込むかどうかと按分が同時に決まる。

  | 選択 | `kind` / `prod` | 意味 |
  |---|---|---|
  | － 取り込まない | `kind:'skip'` | 一覧には残るが取り込まない |
  | 全額（100%が生産活動） | `prod:'all'` | 食材費、活動支援費、おやつ代など |
  | 収入比で自動 | `prod:'auto'` | 給与、電気料など共用のもの |
  | 手入力％ | `prod:数値` | 根拠がある場合 |
  | 福祉事業収入 | `kind:'welfare'` | 按分の分母（訓練等給付費 4113A） |

  一覧で変えると `syncCostProd()` で費目マスタの `prod` にも反映される。
  **按分の変更は明細を作り直さない**（表示のたびに計算するので即反映）。
  「取り込まない」に変えたときだけ、その科目の明細を消すか尋ねる。
- 明細に `tkc:'030|6111|2026-07'` という鍵を持たせているので、
  **同じ月を入れ直しても二重にならず上書きされる**（毎月の推移表は6ヶ月分が重複するため必須）。

### 取り込み漏れの確認（検算）

PDFに載っているその部門の費用科目（4桁コード）をすべて拾い、
**取り込む科目／利用者工賃（アプリで別管理）／取り込まない科目** に分けて割合を出す。
TKCの中だけで突き合わせるので、発生主義と現金主義の違いは影響しない。
結果は `settings.tkcCheck` に残り、設定タブでいつでも見返せる。

> 「生産活動＋福祉事業＝TKCの営業利益」で検算するのは**筋が悪い**。
> TKCは発生主義、アプリの出納帳は現金主義なので必ずずれる。
> 検算は「拾い漏れが無いか」を見るためのもの。

### 読み取りのしくみ

PDFの文字は座標つきで取れる。表の列は月ごとにx座標が決まっているので、
科目コードと同じ高さ(y)にある数字を月の列に振り分ける。
各列でいちばん左が金額（右隣は前年比％なので使わない）。

> **重要①**：pdf.js は `cMapUrl` を指定しないと**日本語を1文字も取れない**（このPDFのフォントは
> 非埋め込みの MS-Mincho/MS-Gothic ＋ `UniJIS-UTF16-H`）。
> また **cdnjs には cmaps が置かれていない**ので、unpkg / jsDelivr から読むこと。
> 「フォントが壊れていて読めない」ように見えるが、原因はこれ。

> **重要②**：前年比％（`58.4` のような小数）は**必ず除外**すること。
> ％は右そろえのため桁が短いと隣の月の列にはみ出し、金額の代わりに拾われて
> **その月が0円になる**（福利厚生費の4月が0円になる不具合があった）。

**読み取りが正しいかの確かめ方**：月ごとに
`収入(4113) − 費用(6xxx の4桁コード合計) = TKCの営業利益` が成立する。
部門030・031とも令和8年2〜7月の全6ヶ月で一致することを確認済み。

## 保存先

1. **クラウド未設定**（初期状態）… そのパソコンの localStorage に保存。
2. **クラウド設定済み**… Firebase Authのメールログイン＋Firestore。
   `shuro_kaikei/{メールアドレス}` 配下に `entries` サブコレクションと
   マスタ（jobs/costs/settings）を持ち、`onSnapshot` でリアルタイム同期。

### クラウドを有効にする手順

1. Firebaseコンソールで新規プロジェクトを作る（例 `ymproject-shuro`）
2. Authentication → 「メール／パスワード」を有効化
3. Firestore Database を作成（本番モード）→ ルールに `firestore.rules` の内容を貼る
4. プロジェクトの設定 → ウェブアプリを追加 → firebaseConfig をコピー
5. アプリの「設定 → クラウド共有 → クラウドの設定」に apiKey などを貼って保存

> **注意**：PowerShellのパイプで `vercel env add` をするとBOMが混入して認証が全滅する。
> 設定はアプリのUIから貼り付けるか、Vercelの管理画面から入れること。

## 移行時に見つかった既存Excelの入力ミス

`出納帳` の 2025年12月分のうち7件で、**入金日が1年ずれて2026年12月**になっている
（例：2025/12/10 清掃 徳里住建 → 入金日 2026/12/10）。
アプリでは日付をカレンダーから選ぶため同じミスは起きないが、
取り込んだデータは元のままなので「明細」タブから直すこと。
